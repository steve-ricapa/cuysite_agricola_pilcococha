1. Stack tecnológico final
Mi stack recomendado sería:

└── React

        └── Tailwind CSS v4
            ├── shadcn/ui
            ├── Lucide React

            ├── Embla Carousel

            ├── react-map-gl
            ├── Sonner
            └── Lenis (opcional)

¿Por qué Next.js y no React + Vite puro?
React actualmente recomienda comenzar los proyectos nuevos con un framework cuando se trata de construir sitios o aplicaciones reales. Para Pilcococha usaría Next.js App Router, porque nos resuelve de forma integrada:
- SEO.
- renderizado estático.
- optimización de imágenes.
- optimización de fuentes.
- metadata.
- rutas.
- sitemap.
- internacionalización.
- API para el formulario.
- Server Components.
- carga progresiva.
- navegación optimizada.
React recomienda actualmente utilizar un framework para proyectos nuevos, y Next.js App Router utiliza las capacidades modernas de React. React
Además, create-next-app ya puede configurar TypeScript, Tailwind CSS, ESLint, App Router, Turbopack y alias @/* automáticamente. Next.js

6. Librería principal de animación: Motion
Usaría:
pnpm add motion

Motion actualmente recomienda importar desde:
import { motion } from "motion/react"

y permite animaciones, gestures, keyframes, scroll animation y orchestration mediante variants. Motion
No instalaría GSAP inicialmente.
GSAP sería útil si quisiéramos algo extremadamente cinematográfico.
Para Pilcococha, Motion es más que suficiente.
7. Accesibilidad de las animaciones
Toda la aplicación estaría envuelta en:
<MotionConfig reducedMotion="user">
    {children}
</MotionConfig>

Así respetamos automáticamente la configuración del sistema operativo de quienes tienen activado Reduced Motion. Motion puede eliminar transformaciones y mantener animaciones menos agresivas como opacity. Motion
Esto es importante para UX.
